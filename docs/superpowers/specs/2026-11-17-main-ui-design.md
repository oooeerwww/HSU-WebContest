# e-Advisor 메인 UI 설계 (프로토타입)

- 작성일: 2026-11-17
- 대상: HSU 진로로드맵 e-Advisor 웹앱 공모전 (`HSU_e-Advisor_공모전_정리.md` 참고)
- 범위: 메인 화면 + 하단 4개 메뉴 화면의 **샘플 데이터 기반 HTML 프로토타입**

---

## 1. 목적 (Why)

- 공모전 주제: 학업 데이터 기반 **맞춤 전공 추천** + 학년·학기별 **교과·비교과 로드맵** 웹앱 프로토타입.
- 이번 단계 목표: 심사·시연에서 보여줄 **메인 UI의 디자인과 동작**을 먼저 완성한다.
- 우선순위: **디자인 > 기능 동작**. 실제 학교 데이터/외부 API 연동은 이후 단계.

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 메인 화면이 아래 "화면 구성"대로 보이고, 부기 클릭 상호작용이 동작한다.
- 하단 4개 메뉴를 누르면 각 화면이 열리고 **샘플 데이터로 실제처럼 동작**한다.
- 학부·학년이 바뀌면 부기의 과잠(색/문구)이 바뀐다.

**비목표 (이번에 안 함)**
- 3D 부기 (Blender 모델링 → 이후 MCP 연결로 별도 진행)
- 실제 한성대 학사·비교과 시스템 연동, 실제 외부 대외활동 API 연동
- 로그인/회원가입, 서버, DB

**실패 조건 (동작해도 실패)**
- 2D 부기를 3D로 교체하기 어려운 구조 (부기 영역이 다른 코드와 엉켜 있음)
- 샘플 데이터가 코드 곳곳에 하드코딩되어 실제 데이터로 바꾸기 어려움

## 3. 제약

- **HTML/CSS/JavaScript** 로 개발 (사용자 지정).
- 개발 기간: 2026.11.25 ~ 2027.01.04 (약 6주), 시연 2027.01.11.
- 부기 원본 이미지: 사용자가 제공한 2D 부기(남색 몸, 하늘색 볼·등껍질, "HSU" 과잠). 메인 UI 기준 이미지 = 이 부기 이미지.
- 브랜드 색: 남색 `#0B2F6B` 계열 + 하늘색 `#A9C4E8` 계열 (부기 이미지 기준).

## 4. 접근 방식 (Approaches)

| 방식 | 장점 | 단점 |
|---|---|---|
| **A. 순수 HTML/CSS/JS (빌드 없음)** ← 채택 | 파일 열면 바로 실행, 배포 쉬움(GitHub Pages), 팀원 누구나 수정 가능 | 화면이 많아지면 코드 정리 필요 |
| B. React/Vite | 컴포넌트 재사용, 확장성 | 빌드 환경 필요, "HTML로 개발" 요구와 거리 있음 |
| C. 단일 HTML 파일 | 가장 단순 | 4개 화면 + 데이터가 한 파일에 몰려 유지보수 어려움 |

**채택: A.** 사용자가 HTML 개발을 지정했고, 6주 프로토타입·시연 목적에 빌드 도구가 필요 없음. 단, 데이터·부기·화면을 파일로 분리해 C의 단점을 피한다.

## 5. 화면 구성 (메인)

```
┌──────────────────────────────┐
│        3학년 2학기            │  ← 사용자 학년·학기 (크게)
│     IT공과대학 컴퓨터공학부     │  ← 소속 대학/학부 (작게)
│                              │
│          ╭─────────╮         │
│          │ 안녕! 👋 │         │  ← 말풍선 (부기 클릭 시 대사 변경)
│          ╰────┬────╯         │
│             (부기)            │  ← 학부·학년별 과잠 입은 2D 부기
│                              │
│  ┌────────────────────────┐  │
│  │ "정보처리기사 자격증     │  │  ← 에세이형 문구 카드
│  │   잊지 말자!"           │  │     (추천 문구 or 사용자 메모)
│  └────────────────────────┘  │
│                              │
│ [내 정보][대외활동][전공분석][비교과] │ ← 하단 4개 메뉴
└──────────────────────────────┘
```

- 모바일 세로 화면 우선 (학생들이 폰으로 볼 가능성 높음), 데스크톱에서는 가운데 정렬된 폰 폭 레이아웃. *(설계자 판단)*

### 5-1. 상단 정보
- `N학년 N학기` 를 크게, 그 아래 소속 대학(+학부)을 작게 출력.
- 값은 샘플 사용자 데이터에서 읽는다.

### 5-2. 부기 (2D)
- 기본 이미지 위에 **과잠 색상/문구를 학부·학년에 맞게** 바꿔 입힌다.
  - 학부별 과잠 색 매핑 표를 데이터로 둔다 (예: 컴퓨터공학부 = 남색, 디자인 = 다른 색 …). *(색 지정은 설계자 판단, 이후 수정 가능)*
  - 학년 표시: 과잠 문구 또는 소매/배지로 표현. *(구체 표현은 설계자 판단)*
- 구현: 부기를 **SVG**로 다시 그려 과잠 부분 색을 코드로 바꿀 수 있게 한다. *(설계자 판단 — PNG는 색 교체가 어려움)*
- 부기 영역은 `bugi` 모듈 하나로 분리 → 나중에 3D(Three.js 등) 렌더러로 **그 영역만 교체**.

### 5-3. 말풍선 상호작용
- 부기 클릭 → 대사 목록에서 다음(또는 랜덤) 대사 표시 + 부기 살짝 튀는 애니메이션.
- 대사 예: "안녕!", "오늘은 어때?", 상황형 대사(예: "비교과 포인트 120P 남았어!").
- 대사 목록은 데이터 파일로 분리.

### 5-4. 에세이 문구 카드
- 두 종류 문구를 보여준다:
  1. **추천 문구**: 사용자 상황 기반 (예: "정보처리기사 자격증 잊지말자!", 비교과 부족 안내)
  2. **사용자 메모**: 사용자가 직접 쓴 메모를 문구로 표시
- 카드 클릭/버튼으로 메모 작성·수정. 메모는 브라우저 `localStorage`에 저장. *(설계자 판단)*

## 6. 하단 4개 메뉴

모두 샘플 데이터로 동작. 메뉴 클릭 시 해당 화면으로 전환(같은 페이지 내 화면 전환 또는 별도 HTML — 설계자 판단, 기본은 같은 페이지 내 전환).

### 6-1. 내 정보
- 이름, 학번, 학년·학기, 소속 대학/학부, 전공트랙
- 학기별 성적(평점), 누적 평점, 이수 학점 / 졸업 학점
- 과목별 성적 목록

### 6-2. 대외활동
- 스펙용 대외활동 목록 (공모전, 서포터즈, 봉사 등)
- 원래는 **외부 API**로 가져오는 구조 → 이번엔 **샘플 JSON**을 같은 형태로 불러온다 (나중에 API 주소만 바꾸면 되게).
- 분야 필터, 마감일 표시.

### 6-3. 전공 분석
목표: 사용자에게 맞는 **전공(트랙) 추천**.
1. **수강 성적 분석**: 들은 수업 중 학점 높은 과목 → 각 과목에 매핑된 역량(창의력 / 사고력 등) 점수화
2. **설문 검사**: 역량·흥미를 묻는 간단한 설문 실시
3. **추천**: 1 + 2 결과를 합쳐 전공트랙 추천 + 추천 근거 표시
- 역량 결과는 차트(레이더 차트 등)로 시각화. *(설계자 판단)*
- 과목→역량 매핑, 설문 문항, 트랙별 역량 프로필은 모두 샘플 데이터.

### 6-4. 비교과 프로그램
- 한성대 졸업요건: **비교과 포인트 800P**.
- 현재 포인트 / 800P 진행률 표시.
- 진행 중인 비교과 프로그램 목록 (공모전, 해커톤, 외국인 상담 등) + 포인트
- 사용자 관심사·부족 영역 기반 **추천 프로그램** 표시.

## 7. 데이터 구조 (샘플)

데이터는 화면 코드와 분리된 파일에 둔다. 나중에 실제 API/DB로 교체할 지점.

- `user` : 이름, 학번, 학년, 학기, 대학, 학부, 트랙, 메모
- `grades` : 학기별 과목 목록 (과목명, 학점, 성적, 역량 태그)
- `activities` : 대외활동 (제목, 주최, 분야, 마감일, 링크)
- `extracurricular` : 비교과 프로그램 (이름, 유형, 포인트, 기간) + 사용자 이수 내역
- `survey` : 전공 분석 설문 문항
- `tracks` : 전공트랙별 역량 프로필
- `dialogues` : 부기 대사
- `jackets` : 학부별 과잠 색 매핑

## 8. 폴더 구조 (안)

```
/
├─ index.html          메인 + 화면 전환
├─ css/                스타일
├─ js/
│  ├─ main.js          화면 전환, 초기화
│  ├─ bugi.js          부기 렌더링·클릭 상호작용 (3D 교체 지점)
│  └─ screens/         내정보 / 대외활동 / 전공분석 / 비교과
├─ data/               샘플 데이터 (JSON 또는 JS)
└─ assets/             부기 원본 이미지 등
```

## 9. 이후 단계 (이번 범위 밖)

- Blender 3D 부기 → MCP 연결로 제작 후 `bugi` 영역 교체
- 실제 학사/비교과 데이터, 대외활동 외부 API 연동
- AI 활용 (추천 근거 설명, 상담형 챗봇 등 — 공모전 권장 사항)

## 10. 설계자 판단으로 정한 것 (확인 필요)

1. 모바일 세로 화면 우선
2. 부기를 SVG로 다시 그려 과잠 색 교체
3. 학부별 과잠 색 / 학년 표현 방식
4. 메모는 `localStorage` 저장
5. 4개 메뉴는 같은 페이지 내 화면 전환
6. 전공 분석 결과는 레이더 차트
